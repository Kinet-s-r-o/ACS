# Backend area router

Operator session lifetimes: [authentication guide](../docs/authentication.md), `auth/session_settings.go`, `api/session_settings.go`, and `finishLogin` in `api/router.go`. `/users/session-settings` uses Users Read/Write. Missing keys retain 24h local / 1h external defaults; existing sessions and 2FA challenge lifetime are unaffected. Read only the two policy keys during login and fail without issuing a token if loading/validation fails.

Optional [reboot after bootstrap](../docs/bootstrap-reboot.md): template `reboot_after_bootstrap` defaults false. `cwmp/bootstrap_reboot.go`, `handler.go`, and `session.go` gate a recorded reboot task on confirmed bootstrap applications with no pending provisioning or failures. Preserve the option in template CRUD, clone, and transfer; omitted updates retain it. No new indexes or grants.

Automatic template snapshots: [automation guide](../docs/automatic-snapshots.md), Inform handling in `internal/cwmp/handler.go`, `internal/database/snapshot_automation.go`, `snapshot_repository.go` and system-task completion. Both policies check every accepted Inform: Initial uses actual existence and `created_at + delay`; Scheduled uses the latest saved Scheduled snapshot plus interval, falling back to CPE creation time for its first snapshot. No periodic snapshot scanner runs. Preserve job deduplication, atomic snapshot/job/device markers and initial-snapshot protection in deletion and retention.

System tasks cleanup: `internal/api/system_task_clear.go`, `internal/database/system_task_clear.go`, and console `SystemTasks.tsx`. `DELETE /system-tasks/{type}` accepts selected `statuses` (pending/completed/failed) with existing System tasks Delete access. Lock queue rows against dispatch, cancel linked pending CWMP tasks in the same transaction, and preserve sent/processing/waiting work. Keep the legacy `/finished` endpoint compatible. Deleting queued snapshots does not disable their schedule or remove saved snapshots.

Template CPE edit form definitions and validation: [edit windows guide](../docs/cpe-edit-windows.md), `internal/api/cpe_edit_window.go` and `internal/models/cpe_edit_window.go`.

Section authorization: [permission model](../docs/permission-expansion-plan.md), `internal/models/permissions.go`, `internal/database/permission_catalog.go`, `internal/api/permission_policy.go` and `permission_network_fields.go`. Saved roles use the operator catalog with per-section action sets; older permission names below identify internal adapters. New routes and fields require explicit policies. Built-in admin resolves the entire current catalog.

Keep sensitive values out of logs and tests. Database schema changes must remain compatible with the supported PostgreSQL 14–18 matrix.

Dynamic parameter discovery (`internal/cwmp/dynamic_discovery.go`) rechecks the parent with shallow GPN once when a just-discovered wildcard instance returns 9005. Only a successful listing that omits that exact instance permits skipping it and continuing; an advertised instance, fixed-path fault, or failed verification retains the fault. This recovery is independent of the opt-in GPV diagnostic tag and does not suppress GPV faults. Empty discovery must not dispatch an empty GPV list, which would request the entire tree.

CWMP fault context is captured at both HTTP dispatch paths by `internal/cwmp/request_context.go`. New fault messages include the outgoing RPC and its source, and Parameter contains requested paths even for queued GPV tasks. Preserve original codes/messages and exclude values and download URLs from this metadata. Disabling rules/metrics does not disable template Parameter refresh, its dynamic discovery, queued tasks or automatic Inform phase scheduling; template overview/full-tree intervals accept `0` independently.

Global CWMP on/off is `internal/cwmpcontrol/`, persisted by `internal/database/cwmp_control.go` in the existing settings table. Startup must load a valid state before opening listeners; missing configuration defaults on, but invalid/unreadable state fails startup. `GET /cwmp-control` requires `provisioning.read`; `PUT /cwmp-control/on` or `/off` requires full access plus `cwmp.control` and is audited with the requested state in the path. The generic settings writer cannot change this key. Wire the same controller into the CWMP handler, API router, watchdog and system-task worker. Off rejects incoming HTTP with 503/Retry-After before CWMP parsing/auth, cancels bound requests, clears sessions, blocks all connection-request paths and pauses watchdog/worker dispatch. Epoch checks prevent stale responses after rapid off/on; already transmitted commands cannot be recalled. Interrupted worker contacts requeue without deleting linked CWMP tasks, and resume shifts active system-task timers by the paused duration in the same DB transaction. The in-memory controller assumes the project's single ACS process; direct DB edits are not a runtime control API.

UI date/time display uses the validated `ui_datetime_format` setting (`locale`, `dmy`, `ymd`, `mdy`, `iso`). Existing `settings.write` controls updates and `settings.read` controls settings reads; `/meta` exposes only this safe preference alongside branding so every console user can apply it. No schema migration is needed for device parameter freshness: `device_parameters.updated_at` already records upserts, including unchanged values and writable metadata updates, rather than the last value change.

Provisioning conditions (`internal/cwmp/condition.go`, `handler.go`, `condition_exists_test.go`) support `exists('Device.path')` / `NOT exists('InternetGatewayDevice.path.')` for exact object or parameter paths. Session-scoped shallow parent GPN probes precede conditional value GPV; they do not use cached parameters. A missing name or parent fault 9005 means absent; other probe faults remain unknown and evaluation skips the affected rule. Object trailing dots are optional; wildcard and `{prev}` paths are unsupported. Conditions share one evaluation phase rather than running between individual conditional writes. Editing retains the existing `provisioning.rules.write` or `provisioning.write` route permissions; no additional grant is introduced.

`internal/database/compression.go` reconciles metric compression policies independently of retention every minute. Settings use `settings.read` / `settings.write`; `/settings/retention/compression` reports actual policies and compressed chunk counts. Disabling removes automatic policies without decompressing history. Raw samples retain the legacy two-hour default; aggregate minimum ages (8/31/366 days) protect their refresh windows. Operational tables retain PostgreSQL's native large-value compression and existing search behavior, without an age-based compression policy. `TestCompressionPoliciesTimescale` uses an isolated schema when `TEST_DATABASE_URL` points to TimescaleDB.

Device parameter storage keeps device-scoped indexes for CPE reads and writes, plus a small partial index for RX-power inventory lookups. The backend does not build the global Fleet wildcard GIN index or the large Fleet latest-value covering index. Fleet analytics endpoints remain available and use device-scoped lookups, but large Fleet dashboards are not optimized for installations that remove those panels.

Optional [UI-managed DB indexes](../docs/database-indexes.md) use `internal/database/managed_indexes.go` for B-tree presets/catalog/preflight, `managed_index_definition.go` for structured custom definitions over safe columns of `devices` and `device_parameters`, and `managed_index_worker.go` for serialized concurrent DDL, cancellation, restart recovery and ongoing storage enforcement. Custom keys support order and NULL placement, INCLUDE fields and optional exact parameter paths. Full-table estimates include all target rows and variable name widths; budgets are 1 GiB per index and 5 GiB total. `internal/models/database_index.go` holds the ownership registry and PostgreSQL-host disk probe snapshot. Never infer ownership from a name prefix or extend the allowlist to GIN/arbitrary SQL. DB tools Read covers index inspection; Write permits creation/cancellation, and Delete permits removal. Startup and migrations do not create these optional indexes.

External integration contract: [API guide](../docs/integration-api.md) and `internal/api/openapi.json`. Keep the embedded OpenAPI document synchronized with `integration.go` and `api_tokens.go`. The token middleware in `internal/auth/api_token.go` must resolve current permissions without a permissive fallback on lookup failure. `integration_postgres_test.go` runs in an isolated schema when `TEST_DATABASE_URL` is set.

User/role JSON transfers use `internal/api/account_transfer.go` and `POST /users/{import,export}`, `POST /roles/{import,export}` with the shared Users and Roles section's independent Import/Export permission. Export accepts filtered record IDs in display order and selects only portable account fields. Imports are atomic, skip existing names, preserve system roles, validate the live permission catalog and prevent grants beyond the actor's access. Users match roles by name and are always created inactive, without local passwords, 2FA pairings or tokens. Limits are 5 MB and 10000 records; no schema changes are needed.

The operator catalog is consolidated by section. `database/operator_permissions.go` performs its one-time conservative data migration; partial old tab grants never become broader section rights. `api/permission_policy.go` translates internal routes to supported section actions. Fleet Add/Edit/Delete are checked against the persisted list under an owner-row lock shared by all panel writers. User deletion retains last-admin/delegation safeguards and removes account-owned tokens/dashboard records.
