# Frontend area router

Users → top-right actions → Session settings is `components/UserSessionSettingsMenu.tsx`. Users Read can view; Users Write can save local/external lifetimes through `/users/session-settings`. Values use whole minutes, defaults 1440/60, range 5–43200; changes apply at the next sign-in. See [authentication](../docs/authentication.md).

Template General → Bootstrap completion configures optional [reboot after successful bootstrap](../docs/bootstrap-reboot.md). Keep `reboot_after_bootstrap` false for new/legacy forms, preserve it in edit/clone/save, and use existing template edit permission with the shared boolean confirmation. Saving does not immediately reboot ONTs.

Automatic template snapshots: [automation guide](../docs/automatic-snapshots.md), `components/TemplateSnapshotsForm.tsx`, `lib/snapshotSchedule.ts`, Edit template tabs and DeviceDetail snapshot actions. Both policies check each Inform: Initial uses missing-snapshot existence and `created_at + delay`; Scheduled uses the last saved Scheduled snapshot plus interval (CPE creation time if none). Display Initial, Scheduled and Manual in the list/detail and preserve their independent types; scheduled/manual snapshots never replace Initial. CPE Write deletes ordinary snapshots; initial snapshots require CPE Full.

Manual CPE snapshots enqueue Bulk Summon and return a system task (HTTP 202). `components/SnapshotRequestStatus.tsx` follows the owned request until completion/failure; refresh the snapshot list only on successful completion and retain failed-request feedback. Unmounting the UI stops polling while the durable queue keeps processing.

System tasks cleanup (`pages/SystemTasks.tsx`) opens one confirmation dialog with Pending, Completed and Failed checkboxes; default to Completed/Failed. Deletion covers the entire selected group, regardless of search/pagination, using the existing System tasks Delete grant. Show counts and pending-cancellation consequences, preserve selections after errors, and keep Processing/Waiting protected. Backend atomically cancels linked pending CWMP tasks; an enabled snapshot schedule may queue new work afterwards.

Template CPE edit form designer and runtime: [edit windows guide](../docs/cpe-edit-windows.md), `components/CPEEditWindowDesigner.tsx`, `CustomCPEEditModal.tsx`, `CPEEditWindowFields.tsx` and `lib/cpeEditWindows.ts`.

Section authorization: [permission model](../docs/permission-expansion-plan.md), `lib/permissions.ts`, `components/SectionPage.tsx`, `pages/RolesTab.tsx` and route/menu/tab guards. Use `can(section, action)` for actions and `canVisit(section)` for navigation. Each catalog row defines its own actions and covers its existing/future subtabs; CPE overview is independent of inventory. Older permission names below identify internal component adapters.

Table multiselect headers mark their select-all checkbox with `data-table-select-all`. Layout's `lib/tableSelection.ts` handles Ctrl+A (Cmd+A on macOS) through that existing control, selecting the current page without toggling an existing selection off. Text editors retain native selection; modal dialogs isolate the shortcut, and multiple selectable tables require focus in the intended table. Existing permissions and disabled controls remain authoritative.

Bulk-delete buttons use `data-table-delete-selected`, `aria-controls` pointing to the table's stable DOM ID, and `aria-keyshortcuts="Delete"`. The shared Delete handler clicks the existing visible, enabled button, retaining its selection, permissions and confirmation. It ignores text editors, modified/repeated/composing key events and underlying modal content; ambiguous actions require focus in the intended table. Only mark selection-based actions, never dialog confirmation or whole-group cleanup buttons.

Row selection checkboxes carry `data-table-select-row` with the stable record ID. Shift+click or Shift+Space applies the endpoint's new selection state to the inclusive range from the last ordinary checkbox selection in that table. Ranges follow current DOM order, skip hidden/disabled rows, preserve selections outside the range, and never cross tables or modal boundaries. A replaced or reused anchor falls back to selecting only the endpoint.

Every boolean indicator change requires the existing Feedback confirmation dialog in both directions. `BooleanIndicator` owns this confirmation; pass contextual `confirmation` copy for consequential actions and keep its callback free of duplicate prompts. Standalone CPE/settings indicators and draft badge toggles use `lib/booleanConfirmation.ts` or an existing contextual confirmation. Cancel/Escape leaves values unchanged and sends no mutation. Preserve permission/pending checks, operator self-protection and specific CWMP/WAN consequences; ordinary form checkboxes, filters and navigation retain their existing behavior.

Provisioning rule, metric/Health, interface metric and additional polling editors use `components/FieldHelpDialog.tsx` and `HelpLabel`; explanations live in `lib/provisioningFieldHelp.ts`. Every field needs a matching topic. Help expands the same mounted dialog on desktop and opens a nested dialog below 1024px; preserve form/input identity, return focus to the trigger and keep help available through the top-level Field help chooser when editing is disabled. The condition topic reuses the full `ProvisioningConditionHelp.tsx` reference. `tests/provisioningFieldHelp.test.mjs` checks field coverage.

Provisioning Rules reorder through the grip button using `lib/pointerRowReorder.ts` and `lib/dragAutoScroll.ts`. Keep native HTML dragging disabled so wheel events remain available while holding a row. Capture the pointer, resolve the target again after scrolling and on release, and cancel on Escape, pointer cancellation/lost capture, blur or unmount. Existing rule Edit permits explicit order entry as the keyboard alternative; the current full-access/edit permission and filter restrictions still apply.

Operator authentication uses the method tiles in `pages/AuthenticationSettings.tsx`; each module links to its own settings route. RADIUS detail is `pages/RadiusAuthenticationSettings.tsx` at `/settings/authentication/radius`, with a link back to the overview. Authentication Read covers the overview and module details; Authentication Write permits edits/tests. `Users.tsx` assigns the backend-advertised module to each account and only accepts passwords for local accounts. RADIUS server editors use `<Index>` to preserve input focus; secrets are retained by stable server IDs and never persisted in browser storage. Read the [authentication guide](../docs/authentication.md) for transport, recovery and MFA constraints.

Provisioning's header has a CWMP on/off boolean immediately before its menu. Viewing state uses `provisioning.read`; changing it requires full access plus the independent `cwmp.control` grant (listed in RolesTab and granted to the built-in admin at backend startup). Confirm global pause, disable during saves/unknown state, refresh on focus/every 10 seconds, and show pause actor/time using the global date format. This controller affects CWMP and connection requests only; administration remains available for resume.

Table controls reserve the final column (`data-column-fixed="visibility"`, ID `__visibility#0`); place ColumnVisibility alone in that header and matching empty cells in data rows. Actions (`data-column-fixed="actions"`) occupy the penultimate column, followed by the reserved control slot even on tables without a visibility selector. Both columns stay sticky on the right and are excluded from pointer/keyboard reordering. The shared order helper ignores their positions in old saved preferences, preserves explicit header/cell IDs, and moves cells without removing Solid comment anchors. Keep stable IDs on every reorderable data cell and update expanded-row colspans when adding a control column.

ColumnVisibility renders its dropdown through Portal outside sticky table headers and overflow containers. Keep it anchored on scroll/resize, constrained to the viewport with its own list scrollbar, and return focus on Escape or explicit close. Table dropdowns use layer 110, above dialogs (100) and below notifications (120), so subsequent table headers cannot cover them. Center both Actions headers and their cell contents.

ColumnFilter shares `lib/floatingPanel.ts` positioning. Measure its Portal after mounting, reposition on scroll/resize and content size changes, constrain its height to the viewport, and scroll only its body so Apply/Clear remain reachable. Escape closes the filter and returns focus to its trigger before an enclosing dialog handles it.

Active table cells use `components/BooleanIndicator.tsx`: green Yes / red No, a pressed-state button only for authorized editors, and disabled while saving. User toggles retain the existing confirmation and self-deactivation guard (`users.write`). Provisioning rules use `provisioning.rules.write` or `provisioning.write`; template metrics and polling use `provisioning.templates.write` or `provisioning.write`, with full access as required by their handlers. `useMetricActiveToggle.ts` updates definitions through their owning template, preserves all existing configuration, awaits refresh and reports failures; unowned legacy metrics remain read-only rather than using disabled global write endpoints. These controls add no new grants.

Provisioning CPE info fields support an optional `postfix` (up to 32 characters). Preserve whitespace so operators can enter units such as ` dBm`; append it as plain text after the formatted ONT Information value, excluding missing/empty placeholders. The existing `provisioning.templates.write` or `provisioning.write` route grants control edits. It travels with the existing JSON template fields through clone/import/export and needs no schema migration. Keep the editor on `<Index>` so typing a postfix preserves focus.

System settings → General → UI settings persists `ui_datetime_format` through the existing `settings.write` route (`settings.read` to view settings). The safe public `/meta` response loads it for all users via `appName.ts`; saving applies it immediately. Use `lib/dateTime.ts` for displayed timestamps, chart time axes/tooltips, and typed `dateTime` parameter values. Keep numeric `unsignedInt` values, durations and edit payloads raw: Unix timestamps require explicit unit metadata rather than guessing. Device All parameters and Connected hosts expose hideable/filterable Last updated columns using existing `devices.read` access. Host freshness (`lib/parameterFreshness.ts`) is the newest valid `updated_at` among the host/merged Wi-Fi association parameters; it is a record refresh, not a value-change timestamp. Preserve stable table keys and cell IDs when extending those columns.

Metric editors share the Health option `health_show_updated_at` (default false), editable through Provisioning Write. Device health uses CPE overview Read and displays the exact metric parameter's `device_parameters.updated_at` below its value or gauge using `formatDateTime`; a missing timestamp shows an em dash. Grouped gauges label each enabled metric's timestamp separately. Keep the option consistent in `MetricModal.tsx`, `MetricsSettings.tsx`, and `Settings.tsx`, including copy/edit initialization.

Every shared Dialog has a bottom-right resize handle: pointer drag, arrow keys (Shift for larger steps), Home to reset, or click for width/height sliders. Dimensions are local to the open dialog, clamped to viewport bounds on resize, and reset when a side panel opens/closes. Keep form identities and nested-dialog focus behavior intact. This presentation control uses the caller's existing permissions and introduces no API grant.

Drag anywhere on the shared Dialog title bar to move it; interactive header controls retain their own actions. The focusable title bar also supports arrow keys (Shift for larger steps) and Home to restore default size/position. Resize controls include horizontal/vertical position sliders as a pointer alternative. Movement preserves current dimensions and stays within viewport margins, including after orientation changes; pointer capture is released on completion, cancellation and unmount.

Users and Roles share `components/AccountTransferActions.tsx`: Upload then Download beside search, using the shared Users and Roles Import/Export grants. Inventory Add is independent of bulk-operation Write, and firmware upload uses Write. See the permission model for migration and operator action boundaries.

Template editor → Ignored parameters uses the same add/remove row pattern as Dynamic parameters, with `<Index>` to preserve input focus. Existing Templates Edit access controls saving; no new grant is introduced. `ignored_parameter_branches` is included in create/edit/duplicate forms and API types. Explain that full/overview/automatic polling skip these branches, new snapshots use that scope, and old cached values are pruned only by a successful full refresh. Paths end in a dot and may contain one-segment `*` wildcards; e.g. `InternetGatewayDevice.LANDevice.*.WLANConfiguration.*.STAWMMParameter.`.

Template Add/Edit/Duplicate dialogs measure the longest dynamic/ignored branch in the inputs' monospace font and pass an optional `preferredWidth` to `Dialog`. The shared dialog clamps that preference to viewport margins, keeps manual sizing authoritative, and restores the content-derived width on reset. Keep branch fieldsets shrinkable and helper paths wrappable on mobile.

Dynamic parameter rows include `DynamicBranchFaultCodes.tsx`: an inline multiselect with common read fault codes and numeric search across 9000–9999. Empty selection records all faults. Keep selected codes associated with the branch when its path changes, remove its policy when deleting the row, and preserve both through create/edit/duplicate. The existing Templates Edit grant applies. Native checkbox labels and Escape behavior keep keyboard operation within the selector before closing the dialog.
